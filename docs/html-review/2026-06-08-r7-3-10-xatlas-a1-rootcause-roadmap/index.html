0. 一頁摘要

北牆木門西側那一塊（A1，世界座標 x≈[-1.91, -1.52]）走 xatlas C2C 烘焙路徑，其餘北牆走舊 D800／separated 路徑。A1 目前與其餘北牆顏色對不齊，內部被切成 A／B／C／D／E 五塊外觀。五塊皆為使用者確認的 BUG，與 SPP 無關，待查的是根因機制。

本 ROADMAP 的核心任務：用探針把「A1 內部拼塊」與「xatlas 間接光值對比 hybrid 間接光值」量清楚，分辨根因走 R1 或 R2，再決定修法。

獨立背景（與本案各自分線）：先前處理過 A1「整片偏暗」，修法是補回漏採的直接光，已收、使用者肉眼確認偏暗消失。A–E 五塊原本就存在、一直都在，與這條補直接光分屬兩條線；調查時分開看，避免方向被誤導。

1. 硬約束（不可違反）

 1  未經使用者當次明確允許，永遠禁止退回 LIVE fallback；目標全室 hybrid 烘焙。
 2  永遠禁止補保底光／borrow light 這類手段。
 3  使用者實測為權威；讀碼結論與實測矛盾時，預設是自己讀錯。
 4  未確認根因前禁止出修法（先 systematic-debugging）；改材質分支前先讀完整 if (hitType==X) 分支。
 5  量測只量「破圖那一格」；A1 含多種外觀，量平均或量到 B 會誤判。
 6  整塊 A1（含 A–E）須與其餘北牆無縫同色才算過；B 看似正常屬巧合，禁止當基準或當已修好。

2. 現況：A1 被切成 A–E 五塊

區塊 位置 外觀
A 北牆上緣靠梁／天花板交界（A1 頂端、近 beam gap sliver） 斑馬線斜紋
B A1 中段 看似正常（巧合，非基準）
C 北牆中段（A1 範圍內） 烘焙髒斑
D 北牆／西牆交界（西北角） 髒帶

五塊同屬一套 xatlas C2C 架構；瑕疵是否存在已由使用者確認，待查的是根因機制。

3. 根因假設：R1 對 R2（R2 再拆 R2a／R2b）

把 source.md 第 3 節深層假設精煉成一個可證偽判據：A1 valid texel 的 xatlas 間接光值，與其餘北牆 hybrid／D800 間接光值是否一致。

 R1   xatlas 間接光值「本應」等於 hybrid，分裂來自 valid／invalid 拼塊 + alpha 閾值 0.5 邊界跳動
      → 修 alpha policy／dilation 即可，架構保留；決策成本低。
 R2a  目前 smoke package 品質／解析度造成（atlas 僅 946×516、architecture_probe 品質）
      → 重烤更高品質／解析度 package 即可，xatlas 架構保留；決策成本中。
      provisional（暫定）：須重烤高品質／高解析 xatlas 對照才可拍板；無對照時 R2a 與 R2b 無法終局分辨。
 R2b  xatlas C2C 架構與 D800 本質無法對齊（bake 路徑、worldPos 映射差）
      → A1 只要走 xatlas 就會分裂，須改回與其餘北牆相同架構（D800／separated）；決策成本高。
 註   R2a 與 R2b 後續決策成本不同，須分開判定，避免混為一談。

A／C／D／E 初判為同一機制在不同幾何位置的表現：A＝沿 chart 三角邊的 valid／invalid 交替；C＝atlas 低解析＋烘焙雜訊；D／E＝A1 xatlas 西緣與西牆 bake 的 seam。皆待證據確認。

4. ROADMAP（分階段）

階段 0：校正現況（唯讀）

 目標  讓現況理解對齊實際工作區，避開過期行號或文件描述帶來的誤導。
 動作  0a 確認 server port（已測：9001 回 200）並貼正確重現網址。
       0b git diff 確認工作區已套用哪些修法；以實讀 shader 校正行號(6532/6596/6610/6699/6801/7070)。
       0c 開重現圖自驗 6 點(可開／非黑／cameraState／有累積／瑕疵在框／確認載入 a1-c2c-smoke 且非 fallback 空包)，
          確認 A–E 在畫面上。
 判據  A–E 五塊在指定相機視角可見；行號與旗標名與實碼一致。
 產出  現況校正筆記（含已套用修法清單）。

階段 1：探針釘根因（核心）

 目標  用 probe 分辨 R1 與 R2。
 動作  1a probe 54（final source-id）：標出 A1 每格走 1=xatlas／2=legacy_d800_north(北牆)／
          3=west_beam_shadow(西梁陰影)／4=live_trace(即時光追)／5=other_hybrid_or_baked(範圍大)，
          定位 A／C／D／E 來源。
       1b 取「同一世界座標」兩側的間接光值再相比（這是 R1／R2 決勝判據，須兩側湊齊、同基準）：
          hybrid 側＝probe 49（北牆 hybrid pre-albedo radiance，單邊，glsl 6061）；
          xatlas 側＝r7310C1XatlasRuntimeCpuSampleValidLinear(atlasUv)（CPU mirror，與正式 runtime 顯示同走
          valid-linear；InitCommon 2263 對應 shader 1176）。
          CpuTexel 與 probe 56 綠階只適合看單點 texel／alpha 狀態，不可當決勝數值；只跑 probe 49 僅量到 hybrid 一半。
          atlasUv 由 r7310C1XatlasA1NorthWallUvFromWorldPosition(worldPosition) 取得（InitCommon 2215，限 A1 smoke
          bounds：x∈[-1.912,-1.518]、|z+1.874|≤0.006）；worldPosition 由現有 diagnostic 或 probe 32／45 取樣
          （皆輸出 hit 世界座標編碼，使用前先以實機確認 A1 牆面該 probe 有值）。
       1c probe 56（xatlas alpha＋luma 診斷，glsl 6581）：看最終 alpha 與 nearest luma 分佈（runtime 取樣端）。
          backface-ratio 是否壓在閾值 0.5 門檻 probe 56 看不到，須補讀離線工具：
          docs/tools/r7-3-10-c2c-validity-mask.py、packageDir 內 xatlas-c2c-alpha-report.json、
          docs/tools/r7-3-10-c2b-backface-ratio.py。
 判據  同格相等 → 偏 R1；同格系統性不等 → 偏 R2。R2a 對 R2b 無法只靠解析度／alpha 分佈分辨，
       須重烤高品質／高解析 xatlas 對照才可拍板（無對照時 R2a 僅 provisional）。
       alpha 沿三角邊交替 → 解釋 A 斑馬線。
 產出  A1 source-id 圖、xatlas 對比 hybrid 同格間接光差幅（兩側皆 valid-linear）、alpha＋luma 遮罩分佈圖。
 紀律  只量破圖那一格，避開 B。

階段 2：bin 量測佐證（離線交叉驗證）

 目標  用 atlas bin 數值佐證階段 1 的螢幕判讀。
 動作  2a 讀 atlas-patch bin 與 D800 北牆包，對同一世界座標比對 xatlas 對比 D800 間接光值差幅。
       2b 確認 D800／separated 北牆包是否本就覆蓋 A1 區（影響「架構回退」是否等於切回 hybrid 路徑、零重烤）。
       2c D／E 在北牆／西牆交界，須補西側證據：先用 probe 54 定位交界兩側 source-id
          （3=west_beam_shadow、5=other_hybrid_or_baked 範圍大）。D／E 落 5 時，再用 westJoin probe 22/26
          或 owner probe 37/38 拆出實際面（西牆／西牆梁／西南柱…），再讀對應西牆／西梁 package 或 runtime source 量測，
          否則 D／E 接縫根因會缺一側。
 判據  bin 量測與探針結論一致；釐清架構回退成本；D／E 兩側來源皆有證據。
 產出  同座標數值對照表、D800 覆蓋範圍確認、D／E 交界兩側 source-id（含 5 的再拆結果）與西側 package 比對。

階段 3：判定根因 + 修法走向（僅評估，待拍板才實作）

 R2b 成立  提案 A1 退出 xatlas、改回北牆既有架構（D800／separated）為主修法（決策成本高）。
 R2a 成立  提案重烤更高品質／解析度 xatlas package，xatlas 架構保留（決策成本中；須重烤對照才可從 provisional 拍板）。
 R1  成立  提案 alpha policy／dilation 修正為主修法（決策成本低）。
 共通      全程不退 LIVE、不補保底光；A–E 須一起收斂到無縫同色才算過。
 交付      根因報告（含證據行號索引）→ 使用者拍板 → 才進修法循環。
