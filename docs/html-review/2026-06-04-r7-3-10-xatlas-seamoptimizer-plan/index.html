4. seamoptimizer 收尾：烤後接縫校平與驗收

4.1 seamoptimizer 的角色

seamoptimizer 排在 xatlas 與烘焙之後。它的工作是把已經有 lightmap 值的 chart 接縫校平，降低兩側亮度跳變。

4.2 seamoptimizer 啟動條件

4.2.1 xatlas atlas 已完成。

4.2.2 A1 位置已有有效 coverage。

4.2.3 path-traced GI 已烤進 xatlas atlas。

4.2.4 dilation / gutter 策略已有初版。

4.3 seamoptimizer 第一個 spike

4.3.1 輸入：
      xatlas mesh positions
      xatlas lightmap UV
      已烤好的 float lightmap
      atlas width / height / channelCount

4.3.2 輸出：
      seamoptimized-lightmap.bin
      seamoptimizer-report.json
      before-after-seam-diff.png

4.3.3 驗收：
      A1 接縫兩側 luma 跳變下降。
      沒有產生白線。
      沒有產生髒色。
      沒有破壞 OIDN 降噪後的平滑牆面。

4.4 dilation / gutter 的位置

4.4.1 xatlas 負責 chart 與 atlas。

4.4.2 path tracer 負責把 GI 烤進 atlas。

4.4.3 seamoptimizer 負責接縫值校平。

4.4.4 dilation / gutter 負責把 chart 外緣向外補色，避免雙線性取樣吃到空白或錯色。

15.5 C2A.6 hiddenContact 判定：採業界標準 per-texel backface-ratio validity（射線半球測試），不自創法線規則

15.5.1 業界統一機制（單一測試，多條件一次滿足）：
       每個 texel 取表面 sample point（Castaño：用 polygon centroid 確保起點在真實表面上）、沿真實面法線 push off 一點（Unity「Pushoff」避免自交）、
       朝半球射一束 ray／渲染 hemicube，統計命中 front face vs back face 的比例。
       front-face 命中比例 ≥ 門檻 → 有效（valid，要烤）；back face 命中太多 → 該 texel 在幾何內部／背面／被遮蔽 → 無效（invalid，不烤）。
       Unity 命名門檻為「Backface Tolerance」＝必須命中正面的 ray 百分比（0.0＝全部都背面才否決；1.0＝有一條打到背面就否決）。
       Castaño 在 hemicube 把 back face 用特殊 tag 標記，某 texel 的 hemicube 被 tag 佔太多 → 整個 sample 丟棄。
       無效 texel 不烤、標記後由 valid 鄰居 dilation／extrapolation 補（與 §14.0.5 的 alpha=0 n/a + valid-linear 完全對齊）。
15.5.2 為何這一個測試就同時涵蓋使用者三個條件（朝室內？被遮蔽？要不要烤？），不需自創規則：
       - 朝室內：真實面法線的半球大多打到場景 front face ⟺ 此面朝開放空間（房間）。
       - 被遮蔽／在結構內：被樑等實體擋住 → 半球打到 back face／實體 → front-face 比例掉 → 無效。
       - 要不要烤：valid 才烤；invalid → alpha=0、dilation 補。
       用使用者反例驗證（沿真實法線射半球）：
         西樑北端帽（真實法線 -Z，朝北進牆體）→ ray 立刻打進牆／結構 back face → 無效（不烤）。✓
         南牆（真實法線 -Z，朝室內）→ ray 射進房間打 front face → 有效（要烤）。✓ 同 -Z 法線、相反結果，由「ray 打到什麼」決定，不靠位置硬判。
         被樑遮住的天花板 → ray 打到樑 back face／被擋 → 無效（不烤）。✓ 先前的 type-2 自動涵蓋。
15.5.3 對本專案 stack 的關鍵含意：
       (a) 有效性半球必須沿「真實面法線 rawNormal」射，不能用 C1 對邊界面強制朝室內的 bakeNormal——
           否則樑帽會被當成朝室內、ray 射進房間、誤判有效。先前 raw≠bake 的發現（§15.4）在這裡變成硬需求：validity 與 gather 都該用 rawNormal。
       (b) 判定來自「ray 打到 front／back face」，天生不寫死 ID、camera-independent，滿足 §9.2.3／硬規則 1。
       (c) 無效 → alpha=0 → dilation 補，正是 §14.0.5 既定 alpha 契約；業界印證此契約正確。
       (d) 幾何前提（使用者裁示 2026-06-05）：結構接合（樑↔天花板、樑↔牆）應密合、前面是實體 → 射線自然判無效、不烤。
           若模型在這種接合處出現不該有的縫＝建模 bug，修模型；classifier 不為「不該存在的幾何」加特例。
           家具（如衣櫃）刻意離牆的真實間隙才是合法 air-gap：背牆前面有空氣 → 烤暗值（合法、無害、不污染可見面）。
           推論：本機制「前面是實體 vs 空氣」這一條就夠，不需再加相機可見性剔除（先前 OPUS 提的策略 A／B 作廢，因 B 所依據的「有縫被遮天花板」案例不存在）。
15.5.4 接縫是另一個獨立問題（重要：別跟 validity 混為一談）：
       dilation 只填 chart 外圈空白 texel，無法修「同一條邊在 lightmap 兩側 texel 值不同」造成的接縫。
       業界用最小平方 seam optimizer（ands/seamoptimizer，源自 Michał Iwanicki《The Last of Us》講演，非 Castaño Witness 引擎碼，且不在 xatlas 內）：
       data 項要求接縫兩側 bilinear 取樣值相等、lambda 拉回原色、cosNormalThreshold 只處理近共面邊。對齊本頁 §4。
15.5.5 與 §14 的關係（供 CODEX 裁示）：本機制取代 §14.3.1 的自創 rawNormal·inward／occlusion 分類；§14.0.5 alpha 契約維持。
       建議 C2C 不再做「CPU 端 hiddenContact 幾何分類」，改為「bake 半球加 backface-ratio 有效性測試（沿 rawNormal）」＝業界單一機制。
