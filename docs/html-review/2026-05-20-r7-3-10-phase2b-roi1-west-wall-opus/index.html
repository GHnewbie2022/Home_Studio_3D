  1. l-gap-closure-v5：發現西樑 zMax 與西南柱 zMin 同為 2.848，邊對邊零重疊讓 grazing primary ray 透過縫看到外部夜景。修法：柱 zMin 改 2.846，西樑底 zMax 截到 2.846、西南柱北面 yMax 截到 2.525，並重烘 structural island。
  2. mosaic-guard-v1：補 fillR7310C1WestWallBeamShadowGuardTexels() 與 fillR7310C1WestWallSouthwestGuardTexels()，填 hidden texels。
  3. live-direct-v1：把 c1_west_wall_beam_shadow ownership 從 z<2.833 / y<=2.523 擴展到全西牆 bounds（z=-1.874..3.056, y=0..2.905），意圖將整個西牆的直接光交給 LIVE、間接漫射交給 BAKE，addDirectLightAfterBakeLookup=true，並移除 guard column copy。

6. 根因假說

H1 信心 70% BAKE atlas 邊緣 texel alpha 不足

每個 dedicated route 的 SampleValidLinear 走「c.a 加權平均，weightSum<1e-6 退回 nearest」的雙線性。WestWallBeamShadow atlas 公式 atlasUv=((z+1.874)/4.93, y/2.905)，當光線命中接近 z=3.056 或 y=2.905（西牆角落）時 atlasUv→1.0，取樣的 2x2 texels 落在 atlas patch 物理邊界。

若 BAKE 階段該邊緣 texel 對應「被柱遮住、無 valid first-hit」位置，alpha 會是 0 / 接近 0 → 加權結果偏暗或 fallback 到 nearest 仍黑。mosaic-guard-v1 的 fillSouthwestGuardTexels 補的就是這個，但 bilinear 仍會在 guard 邊界 1~2 texel 內混到原本 0。

H2 信心 65% 多 dedicated route ownership 邊界硬切

三面交界處（西樑底 z=2.846、西南柱南 z=2.846、西樑內 z=2.848、西南柱北 y=2.525、西樑底 y=2.515..2.535），相鄰像素分屬：

  • WestBeamUnderShadow（slot 15）
  • WestBeamInnerShadow（slot 14）
  • SwColumnNorthShadow（slot 13）
  • SwColumnInnerShadow（slot 11）
  • Structural island 2 / 5 / 6

每條 route 的 atlas 用不同 patchSlot、不同 UV 公式，過界時直接「離散切換」（無 cross-route blending）。即使每條 atlas 內部 BAKE 完美，切換界線本身會在亮度有 step → 視覺上的硬邊黑線。

H3 信心 35% LIVE 階段殘留 AO 硬邊

all-off-live 圖中暗化區存在，但雜訊重，難以直接證明是 AO 漸層或殘留幾何縫。l-gap-closure-v5 修了「西樑 / 柱零重疊」幾何縫，但西樑底（y=2.525）↔ 西南柱頂（y=2.525）仍是邊對邊；西樑底（z=2.846）↔ 西南柱南（z=2.846）也是邊對邊。光線斜入射時仍可能在 2 個 box 共邊處取到 hit-miss 邊界，產生 1px 黑點。

H4 信心 50% westWallBeamShadow ownership 過度延伸

live-direct-v1 把 west_wall_beam_shadow ownership 擴展到 z=3.056，包含西南柱（z=2.838..2.858, x=-1.91..-1.75）背後的牆段（x∈[-1.92, -1.91]）。這段牆被柱遮住，BAKE 階段該位置 first-hit 是柱不是牆，若 west_wall_beam_shadow atlas 沒重新烘出這段「躲在柱後」的牆，邊緣 texel 仍是舊資料或 0。SEAM_GUARD_Z_MAX=2.833 常數被遺留就是這段風險的化石。

7. 建議下一步驗證序列

步驟 1：隔離 H1 vs H2

  • 若任一 c.a < 0.5 → H1 命中。
  • 若 4 個 c.a 都接近 1，但相鄰像素 route id 不同造成 luma step → H2 命中。

步驟 2：隔離 H3

步驟 3：隔離 H4

Q4：是否加 cross-region tri-linear blend？ CODEX 建議暫緩當正式修法。這條線優先維持精確光學物理表現；blend 可以作診斷對照，但正式修法應先處理 ownership、guard coverage 或 package coverage。

第 10 節：H4 診斷實驗是否可即時做？ 可以作低風險診斷，條件是用 debug flag 或臨時 branch，只改 runtime classifier，不重烘、不帶入正式修法。觀察重點是 z<2.833 西側段是否改善，以及 z>2.833 是否按預期惡化。
第 10 節：是否有 H5？ 有一個候選 H5：三面共邊處的 primary-hit face tie-break / epsilon 分類跳動。即使 atlas 內容正確，ray 在西牆、西樑、西南柱共邊附近可能因距離非常接近而在相鄰 pixel 命中不同面，進一步觸發不同 route。probe 要在 routeId 前面加 hit object / normal / distance 記錄。

補充 1：P1 sample grid 在「D 內角凹點 ±2px」可能不夠

補充 2：luma 閾值要同時記 max abs step，不只 mean delta

  • P1 / P2 都需要這兩個指標。

補充 3：P1 / P2 在 spp=1 雜訊下不可靠，需要 spp>=200

所有同視角截圖都是 target-samples=1，這對「肉眼看黑線是否存在」夠用；但對「luma step 量測」會被 LIVE 1spp 雜訊蓋掉。建議：
