# R7-3.10 xatlas A1 北牆破圖修復經驗紀錄

日期：2026-06-10  
範圍：xatlas A1 北牆低處破圖、per-tile bake sampler 綁定、驗證紀律、後續 OIDN 髒斑線  
狀態：北牆破圖已由使用者肉眼驗收通過；髒斑與 OIDN 另開分支追

---

## 一句話

北牆 A1 低處破圖的真正原因是 xatlas bake 在右半 tile render pass 讀到錯誤的 normal sampler，導致 normalLen 變 0、texelValid 變 false，shader 直接回傳 0；修法是在每個 tile/sample render 前重新綁回 xatlas bake 專用 worldPos/normal texture。

---

## 最終根因

```
raw zero
  ← xatlas bake early return 0
  ← r7310C1XatlasBakeTexelValid == false
  ← normalLen == 0
  ← tile(1,0) render pass 讀 normal sampler 時讀到全 0
  ← tR7310C1FullRoomDiffuseAtlasTexture 在 tile loop 期間被 runtime / screenCopy 相關狀態換掉
```

關鍵分界：

```
1.  worldPos sampler 正常
    - tile(1,0) 讀到 worldPos.w=1
    - worldPos.z 維持 -1.874，對到北牆平面

2.  normal sampler 異常
    - tile(1,0) 讀到 normalLen=0
    - metadata 內同區域 normal=(0,0,1)，資料本身正常

3.  問題發生在 render pass 狀態
    - probe 80 顯示同一組 texelFetch 座標，在 tile(0,0) 讀 normalLen=1，在 tile(1,0) 讀 0
    - upload 內容可用，尺寸也正確；錯誤落在 per-tile 綁定/狀態刷新
```

---

## 修法

修法位置：

```
js/InitCommon.js
  - 新增 refreshR7310C1XatlasBakeTextureUniforms(prepared)
  - xatlas bake capture 開始前呼叫一次
  - tile/sample render 前再次呼叫
```

重接內容：

```
tR738C1BakeAtlasTexture = prepared.textures.worldPos
tR7310C1FullRoomDiffuseAtlasTexture = prepared.textures.normal
pathTracingMesh.material.uniformsNeedUpdate = true
```

修法性質：

```
這次屬治本修法。
原因是直接修正 bake 讀 normal 的接線與刷新時機，讓低處 texel 重新通過 gate 並參與 bake。
它沒有靠 alpha 補洞、鄰格借光、runtime 後補亮度來遮住破圖。
```

## 最重要的驗證教訓

### 1. 正式 package / CPU 讀檔優先

本輪曾有一次錯誤回報：瀏覽器即時 capture 顯示低處 luma 0.037、非零 83.6%，後來 CPU 讀正式 package 證明那是污染結果。

後續規則：

```
1.  修復宣告以正式 runner 產出的 package 為準。
2.  關鍵數值用 CPU 直接讀 package / metadata 核對。
3.  瀏覽器即時 capture 只當快速方向探測，不當最終驗收。
4.  若即時 capture 與 package CPU 結果衝突，以 package CPU 結果為準。
```

### 2. headless / RAF / screenshot flush 容易污染狀態

本輪為了讓 headless 頁面在背景跑完，曾使用 MessageChannel RAF patch 與 screenshot flush。這些方法可協助診斷，但會增加狀態污染風險。

後續規則：

```
1.  可以用它們找方向。
2.  不用它們做通過宣告。
3.  每次 capture 前 fresh reload。
4.  連續 capture 結果出現反常時，先懷疑 render target / texture state 殘留。
```

### 3. probe 要先做常數校準

本輪多次誤判來自「probe 位置有輸出」與「probe 輸出代表想測的物理量」混在一起。

後續規則：

```
1.  新 probe 先輸出固定常數。
2.  常數在目標區讀得到，再輸出物理量。
3.  常數讀不到時，先查是否沒進該 branch、是否 shader cache 沒更新、是否 render pass 狀態異常。
```

### 4. shader cache-buster 必須同步

本輪 probe 58/60/61 一開始其實沒載入，新舊 shader cache 造成誤判。

後續規則：

```
1.  改 shader 後同步更新 shader query cache-buster。
2.  若 Home_Studio.js 也被瀏覽器 cache，HTML script query 也要更新。
3.  reload 後先用 fetch no-store 或頁內版本訊號確認新 shader 已載入。
```

### 5. tile bake 要特別防 texture unit 被覆寫

本輪真正破點出在 tile loop 期間。tile(0,0) 正常，tile(1,0) 壞，這種錯誤很容易被單 tile 或左半區 sample 掩蓋。

後續規則：

```
1.  xatlas bake 相關 sampler 在每個 tile/sample render 前刷新。
2.  screenCopy / tPreviousTexture / runtime atlas 更新後，重新確認 bake 專用 sampler。
3.  probe 設計要按 tile 分段統計，不只看整體 median。
4.  若 atlas 寬高跨 tile，至少檢查 x=511/512 與 tile(1,0)。
```

```

    - 先用 CPU 讀 package 與 metadata。

    - worldPos.w

    - tile(0,0) / tile(1,0) 分開統計。

    - 正式 runner 產出 package。
    - CPU 讀 package 指標通過。
    - runtime pointer 指向新 package。
```
